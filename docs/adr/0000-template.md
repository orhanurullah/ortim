# ADR-0000 — Short imperative title (≤ 70 chars)

**Status**: proposed | accepted | superseded by ADR-NNNN | deprecated
**Date**: YYYY-MM-DD
**Decider(s)**: name(s) or role
**Related**: ADR-NNNN, ADR-NNNN (optional)

## Context

What problem are we deciding about? What constraints were in play?
What did NOT shape the decision (so future you doesn't re-litigate
non-issues)? 1-3 short paragraphs. Cite the commit / PR / proof-point
that triggered the decision if applicable.

## Decision

The chosen approach, stated in one sentence. Then a short bullet list
of what it actually changes:

  * Files / interfaces / configs added or modified.
  * Behaviors locked in (or explicitly left open).

## Consequences

Honest accounting — both sides of the trade.

**Positive**

  * What gets easier or more predictable now.

**Negative**

  * What gets harder / costlier / locked in.
  * Known edge cases this approach handles poorly.

**Neutral / deferred**

  * Decisions explicitly put off for later.

## Alternatives considered

Each rejected option in one line: "Option X — rejected because Y."
Skip this section only if no real alternative existed.

## Notes

Anything the four sections above don't cover: links to external
references, follow-up items, retention timeline if applicable.
